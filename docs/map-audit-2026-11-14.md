# Weather map audit

**Release 0.2.0 · Public main `35c8b67` · November 14, 2026**

All six findings from this release were fixed in build `6b8e3cd2ddcf` and deployed to Home Assistant on November 15. The retest results follow the original observations. [Audited revision](https://github.com/sitapix/iweather-card/commit/35c8b675791f19608101ded73a7e1b62d62405da) · [Public demo](https://sitapix.github.io/iweather-card/)

## Fix first

### 1. Historical radar frames are labeled “Forecast”

On the public demo, I opened precipitation and pressed Left three times. The map displayed **Forecast Sunday 1:20 PM** on an observed frame. The timeline sets one title for the entire one-hour view even though the renderer distinguishes observations from projected frames. A person checking whether rain has already passed sees the wrong description. [Timeline selection](https://github.com/sitapix/iweather-card/blob/35c8b675791f19608101ded73a7e1b62d62405da/src/map/views.ts#L941) · [RainViewer frame definitions](https://www.rainviewer.com/api/weather-maps-api.html)

**Acceptance check.** Scrub from the last observed frame to the first modeled frame and back. The visible label and accessible time value identify the source and local time on both sides. With observations alone, every frame is identified as radar.

### 2. Full-screen touch controls lack a simple way to pan and zoom

The stylesheet hides both 44-pixel zoom buttons when the primary pointer is coarse. The live map handles a two-finger tap for zooming out. The raster fallback handles pinch, and a tap on empty ground shrinks the home pin. The arrow keys pan, but a person using only a pointer has no equivalent way to move around the map without dragging. I verified this finding in the interaction code and stylesheet. [Touch styles](https://github.com/sitapix/iweather-card/blob/35c8b675791f19608101ded73a7e1b62d62405da/src/iweather-card.css#L1151) · [Map interactions](https://github.com/sitapix/iweather-card/blob/35c8b675791f19608101ded73a7e1b62d62405da/src/map/moves.ts#L132) · [Live gestures](https://github.com/sitapix/iweather-card/blob/35c8b675791f19608101ded73a7e1b62d62405da/src/map/pinch.ts#L149)

**Acceptance check.** On a touch-primary device, zoom in, zoom out, and move the center north, south, east, and west using taps alone. Run the same check with WebGL disabled. Showing the existing zoom buttons and providing a tap-to-pan control would cover both paths. [WCAG 2.5.1 Pointer Gestures](https://www.w3.org/WAI/WCAG22/Understanding/pointer-gestures.html) · [WCAG 2.5.7 Dragging Movements](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html)

### 3. The full map hides base-map attribution

The compact tile shows provider text. On the expanded map I had to open **Map Data** to see the credits, and the expanded credits contained no link to OpenStreetMap’s copyright page. The raster fallback uses the public OpenStreetMap tile service and puts its credit in that same collapsed panel. That service explicitly requires visible attribution. [Credit generation](https://github.com/sitapix/iweather-card/blob/35c8b675791f19608101ded73a7e1b62d62405da/src/map/markup.ts#L260) · [Credit visibility](https://github.com/sitapix/iweather-card/blob/35c8b675791f19608101ded73a7e1b62d62405da/src/iweather-card.css#L1266) · [OSM tile policy](https://operations.osmfoundation.org/policies/tiles/#2-attribution-and-licensing)

**Acceptance check.** Open the default raster map and verify that its linked attribution is visible before interacting. Check desktop and phone layouts with the timeline open. Give the vector basemap its applicable provider credits, retain **Map Data** for weather-source details, and honor custom tile configurations. [OSMF attribution guidance](https://osmfoundation.org/wiki/Licence/Attribution_Guidelines#Interactive_maps)

## Interaction and loading

### 4. A data refresh can close the layer menu mid-selection

In a fresh browser session, I opened the map and opened **Map layers** with Enter. The button changed from expanded to collapsed as the map loaded, with no further input. Once loading settled, selecting **Wind** succeeded. The redraw replaces the view’s entire contents, including the menu and its focused control. [Redraw implementation](https://github.com/sitapix/iweather-card/blob/35c8b675791f19608101ded73a7e1b62d62405da/src/map/views.ts#L1392) · [Layer menu markup](https://github.com/sitapix/iweather-card/blob/35c8b675791f19608101ded73a7e1b62d62405da/src/map/markup.ts#L118)

**Acceptance check.** Open the menu before radar or basemap data arrives and focus a layer. Deliver the pending data. The menu stays open, the same choice keeps focus, and Enter selects it. Apply the same check to the focused timeline during a refresh.

### 5. The timeline lacks time semantics and standard slider keys

The accessible slider exposes a frame index and has no `aria-valuetext`. Its handler steps on Left and Right only. In Chromium, Left selected 1:30 PM and Home left it at 1:30 PM, partway through the range. The browser’s accessibility tree exposed a slider named **Time**. [Slider markup](https://github.com/sitapix/iweather-card/blob/35c8b675791f19608101ded73a7e1b62d62405da/src/map/markup.ts#L113) · [Value update](https://github.com/sitapix/iweather-card/blob/35c8b675791f19608101ded73a7e1b62d62405da/src/map/views.ts#L971) · [Key handling](https://github.com/sitapix/iweather-card/blob/35c8b675791f19608101ded73a7e1b62d62405da/src/map/views.ts#L1074) · [WAI-ARIA slider pattern](https://www.w3.org/WAI/ARIA/apg/patterns/slider/)

**Acceptance check.** Prefer a labeled native range input. All four arrow keys step through available frames, Home and End reach the first and last frames, and the accessible value gives the localized date and time in Home Assistant’s configured time zone. Retain tap-to-seek and continuous visual interpolation. Verify with a touch screen reader as well as a keyboard.

### 6. The 12-hour forecast keeps starting requests after the sheet closes

With reduced motion enabled, I opened **12h**, waited for its first forecast, pressed Escape and verified that the sheet had closed. During the next 3.3 seconds Chromium recorded **10 new GeoMet requests**. The compact precipitation preview was disabled by reduced motion. The large map starts a batch that loads forecast hours progressively. Closing the sheet aborts the short forecast, while the 12-hour loader continues through its queue. [Map close](https://github.com/sitapix/iweather-card/blob/35c8b675791f19608101ded73a7e1b62d62405da/src/map/views.ts#L425) · [Grid loading](https://github.com/sitapix/iweather-card/blob/35c8b675791f19608101ded73a7e1b62d62405da/src/map/views.ts#L603) · [Forecast queue](https://github.com/sitapix/iweather-card/blob/35c8b675791f19608101ded73a7e1b62d62405da/src/map/rain-grids.ts#L163)

**Acceptance check.** Give each active forecast load an abort signal. When its last visible consumer closes or disables online data, cancel in-flight requests and stop dequeuing hours or trying alternate providers. With a second visible consumer using the same grid, the shared load should finish. A canceled load should retry normally on reopen. [AbortController](https://developer.mozilla.org/en-US/docs/Web/API/AbortController/abort)

## Fix verification · November 15, 2026

| Finding | Verified behavior in build `6b8e3cd2ddcf` |
| --- | --- |
| Radar source | The last observation reads **Observed radar**. The next modeled frame reads **Forecast**. Stepping back restores the radar label. An observation-only map keeps its radar label through the last frame. |
| Touch navigation | The vector and raster maps both moved north, south, east and west through the direction buttons. Both zoom buttons worked. On the phone simulator the controls measured at least 44 × 44 CSS pixels. |
| Attribution | The expanded raster map showed the linked OpenStreetMap copyright credit on opening. The vector map also linked to OpenFreeMap and OpenMapTiles. The timeline cleared those links on phone and desktop layouts. A custom tile template omitted the default credits. |
| Focus during loading | An open layer menu and its focused choice survived radar delivery and a Home Assistant weather update. Selecting the choice still worked. A focused native range stayed attached through a map redraw. |
| Timeline semantics | The native range responded to Home, End and all four arrows. Its accessible value included the source and the selected date and time in the configured America/Chicago zone. A native input event also selected the corresponding radar frame. |
| Forecast cancellation | Closing after the first GeoMet hour aborted the in-flight requests and started zero additional hours. Reopening retried. With a second visible consumer, the shared forecast finished downloading. |

Chromium exercised the release served by Home Assistant with vector, raster and custom tiles. Safari on a touch-primary phone simulator passed 25 checks on the vector map and 23 on raster. The browser checks used controlled weather responses to reproduce source boundaries and pending requests. The installed module URL and the SHA-256 digests of all 47 files served by Home Assistant were verified.

The Node suite passed 3,964 test executions across four time zones. Types, lint, formatting, the production build and compatibility checks passed. The local Vitest browser server could not bind its port. Physical VoiceOver and TalkBack testing remains outstanding.
